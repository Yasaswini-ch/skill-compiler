`skillcompiler/llm.py:84` returns `response.text or ""` and never reads the finish reason, so a MALFORMED_RESPONSE (or any blocked or empty candidate) becomes `""` with no exception; SDK 2.33.0 only warns (`google/genai/_common.py:707`, "MALFORMED_RESPONSE is not a valid FinishReason").
`llm.py:153-164` then treats `""` as a success: it counts the call (160), caches it (163, so `--cache` would keep replaying an empty answer) and returns it (164); the retry loop (148-159) only reacts to exceptions.
The harness still recovered because `checker.py:46` rejects empty output and the runner retries: run 3, t04 step 6 got two empty replies (1.3 s each) and then `0.00` (`benchmark/output/run3/traces/t04_harness.json`); that the warning caused them is likely, not proven.
Suggested fix (Yasaswini decides): in `_generate`, read `response.candidates[0].finish_reason` and raise when `response.text` is empty so the existing backoff loop retries it; at minimum skip `stats.calls` and `cache.put` when `not text.strip()`.
`benchmark/client.py` has the same `or ""`, so plain mode would score an empty reply as a failed answer; I can add retry-on-empty there (it is in benchmark/) if you agree.
